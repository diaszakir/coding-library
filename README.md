# DevLibrary

Локальная учебная платформа на Next.js, React и TypeScript. Каждый человек запускает свою копию, создаёт собственные курсы и хранит конспекты, проекты и прогресс на своём устройстве. Регистрация и внешняя база данных не нужны.

Переносимая версия начинается с пустой библиотеки. Личные курсы, прогресс, резервные копии и история исходного проекта в неё не включаются.

## Docker

Нужен Docker с Compose. В папке проекта:

```sh
docker compose up --build -d
```

Открой [http://localhost:3000](http://localhost:3000). Инструкция для ИИ: [http://localhost:3000/agents](http://localhost:3000/agents).

```sh
docker compose logs -f
docker compose stop
docker compose start
```

Данные лежат в постоянном томе `library-data`, подключённом к `/app/library-data`. Пересборка и `docker compose down` сохраняют их. `docker compose down -v` удаляет том вместе с библиотекой.

Образ всегда собирается с пустым каталогом. `.dockerignore` исключает личные материалы; сборщик создаёт нейтральные файлы реестра. Образ работает от непривилегированного пользователя. Доступность проверяется через `/api/health`.

## pnpm

Нужны Node.js **22.13 или новее** и **pnpm 11.25.0**. Версия pnpm зафиксирована в `package.json`, зависимости — в `pnpm-lock.yaml`.

При необходимости установить pnpm можно командой `npm install --global pnpm@11.25.0`. Далее все команды проекта выполняются через pnpm:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Для обычного запуска:

```sh
pnpm build
pnpm start
```

Адрес по умолчанию: [http://127.0.0.1:3000](http://127.0.0.1:3000), только на этом устройстве. Команды одинаковы для Windows, macOS и Linux. Создай `.env` из `.env.example`, чтобы изменить адрес, порт или папку данных. Не запускай несколько серверов с одной библиотекой одновременно.

## Создание своих курсов

Открой **Управление библиотекой → Добавить курс**:

- **Написать на сайте**: введи название, вставь текст или выбери `.md`, `.markdown`, `.txt` до 2 МБ. Пустой курс можно наполнить позже через **Добавить тему**.
- **Из папки**: выбери папку с Markdown-конспектами. Приложение создаст свою копию, сохранив оригиналы. В Docker путь относится к контейнеру.
- **С помощью ИИ**: открой `/agents`, скопируй готовый запрос и укажи тему, уровень и источники.

Заготовка: [`templates/course-folder`](templates/course-folder/Notes/01-introduction/README.ru.md).

```text
my-course/
  Notes/
    01-introduction/
      README.ru.md
      README.en.md
    02-practice/
      README.ru.md
```

Одна папка темы — один урок. Достаточно одного языка. Номера папок задают порядок. Видео и архивы не копируются вместе с конспектами.

Команды для пользователя или ИИ-агента:

```sh
pnpm course:create --title "Мой курс"
pnpm course:create --title "Мой курс" --note ./lesson.md --language ru
pnpm course:create --title "Мой курс" --path ./my-course
pnpm course:create --help
```

Импорт в работающий контейнер:

```sh
docker compose cp ./my-course devlibrary:/tmp/my-course
docker compose exec devlibrary node scripts/create-course.mjs --title "Мой курс" --path /tmp/my-course
```

После изменения файлов импортированного курса используй **Обновить из файлов** или `pnpm import:courses`. Удаление перемещает курс в корзину. Редактор делает резервные копии и отклоняет сохранение поверх изменённого извне текста.

Подробнее: [собственные курсы](docs/custom-courses.md), [инструкция агентам](docs/agent-guide.md), [правила материалов](docs/ai-course-rules.md). Краткая машинная инструкция доступна по `/llms.txt`.

## Данные и перенос

В переносимом репозитории данные по умолчанию находятся в `./library-data`, исключённой из Git. Порядок выбора папки: `DEVLIBRARY_DATA_DIR` → `dataDirectory` в `courses.config.json` → `./library-data`. У исходной установки прежний путь сохранён через её локальный `courses.config.json`.

```text
library-data/
  courses/<id>/    # Markdown и связанные исходники
  inbox/          # новые папки перед импортом
  library.json    # каталог, корзина, идентификаторы
  progress.json   # прогресс, проекты, время, позиции чтения
  backups/        # прежние версии конспектов
```

Для полного бэкапа останови приложение и скопируй всю папку данных. Из Docker её можно выгрузить так:

```sh
docker compose stop
docker compose cp devlibrary:/app/library-data ./library-backup
docker compose start
```

На другом устройстве перенеси исходный репозиторий и запусти его: получится пустая библиотека. Свои прежние материалы при необходимости перенеси отдельной резервной копией и укажи путь в `DEVLIBRARY_DATA_DIR`. В Docker восстанови файлы в `/app/library-data` при остановленном приложении.

`DEVLIBRARY_SEED=empty` задаёт пустое наполнение только **новой** библиотеки и никогда не очищает существующие данные. CLI принимает `--data-dir ./another-library`; сервер должен использовать тот же путь, чтобы видеть её курсы.

## При необходимости: домашняя сеть

Основной режим — отдельная локальная копия у каждого человека. Чтобы открыть свою установку на телефоне в той же сети, создай `.env` из `.env.example`:

```dotenv
DEVLIBRARY_BIND_ADDRESS=0.0.0.0
DEVLIBRARY_ALLOW_NETWORK=true
```

Перезапусти Docker: `docker compose up -d`. Открой `http://<локальный-IP-компьютера>:3000`. Для pnpm дополнительно задай `DEVLIBRARY_HOST=0.0.0.0` и перезапусти сервер. Разрешены частные IPv4-адреса; изменения требуют запроса с того же origin. В этом режиме все устройства работают с **одной** библиотекой без разделения пользователей. Для доступа только с этого компьютера оставь значения по умолчанию.

## Чистый Git-репозиторий

Экспорт переносимого кода из исходного проекта:

```sh
node scripts/prepare-portable.mjs --output ../devlibrary-portable
```

Папка назначения должна быть новой или пустой. Экспорт использует явный список исходников, исключает старый `.git`, `.openai`, личные курсы, учебные данные, прогресс, отчёты, `.env` и резервные копии. Создаются пустые каталог и реестры. Старая Git-история не переносится.

`--in-place` предназначен только для изолированной стадии Docker-сборки и отказывается работать в Git-checkout. После проверки экспорта можно выполнить в новой папке `git init -b main`, `git add .`, `git commit`. Для работы приложения remote и push не нужны.

## Проверки

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm build
docker compose config
```

Тесты используют временные библиотеки и проверяют создание и импорт курсов, оригиналы, резервные копии, конфликты, корзину, прогресс, ограничения запросов и отсутствие личных материалов в переносимом экспорте.
